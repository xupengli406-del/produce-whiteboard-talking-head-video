# 口播、黑板、人物与笔记的协同编排

编排单位是“一个需要被理解的语义动作”，例如提出问题、建立对象、说明阻碍、增加条件、对比方案、给出证据、总结结果。镜头模式和元素出现都依附这些动作，不按固定秒数轮流切换。

## 四条独立但相互约束的时间线

| 时间线 | 控制内容 | 更新触发 |
|---|---|---|
| 口播/字幕 | 真实发言与忠实翻译 | 实际音频的语义组起止 |
| 黑板 | 对象出现、连接、强调、局部观察与回总览 | 观众理解当前句子所需的关系发生变化 |
| 真人 | 位置、尺寸、裁切、可见性 | 交流任务变化或给当前图解让位 |
| 中文笔记 | 章节、当前项、已讲项 | 一个要点被引入、讲清或进入小结 |

这四条时间线共用口播时间基准，但无需同时动作。每一句话都使人物、笔记和黑板一起变动，会产生抢夺注意力。为一个语义事件选择主要动作，其他区域提供稳定上下文。

每片字幕都按[字幕关键词放大](subtitles-and-emphasis.md)编排真实重读锚点。关键词放大及邻字让位是一项主要注意力动作，画板、人物与笔记不应在同一时刻各自做无关的大动作。字幕强调完成后保持至该条退出；不能为下一项图解提前回缩字幕来清场。

## 从口播到事件表

1. 核实内容与授权，区分真实口播、可补录语句、纯视觉信息。对已有视频，优先从实录中选择真实钩子与结构，不合成未说过的话。
2. 对已有录像先完成[原声精剪](implementation.md#原声精剪先于字幕)，再将保留口播切成完整语义组，标记最终音频起止与关键词落点。先明确观众需要理解什么，再安排画面；不能把未剪干净的重说仅在字幕中改成一句。
3. 为每个语义组指定对象、关系、所需旧上下文和当前焦点。若不需要图解，可让人物说完并保留简洁笔记。
4. 为黑板维护持续状态，决定这一步增加什么、聚焦什么、保留什么。旧对象可低亮或出视口，不必反复删掉重画。
5. 根据交流任务和可用空间选择人物模式，再确定笔记是否推进。字幕始终跟随真实发言。
6. 生成可执行事件表，按实际音频校准。先检查开场与最复杂片段，再完成全片编排与实际导出审阅。

建议表中每行是一项可执行动作。并发动作可共享 `group_id`，动作之间存在先后关系时显式记录，不能只依赖作者记忆。

| 字段 | 含义与要求 |
|---|---|
| `event_id` / `group_id` | 稳定唯一标识与所属语义动作 |
| `start` / `end` | 相对最终口播音轨的秒数，不能由字数估算后不复核 |
| `speech_text` | 触发本动作的真实口播语义组 |
| `anchor` | 关键词、停顿或要点完成的具体音频落点 |
| `intent` | 提问、对象建立、因果、比较、证据、条件、回顾等 |
| `segment_role` | 高光预告或正文；前置高光不参与正文章号计数 |
| `chapter_id` / `point_id` | 当前章节与章内要点，各自独立 |
| `board_before` | 动作前存在的对象、连接和视口状态标识 |
| `board_action` | 新增、连接、圈出、变亮、变灰、聚焦、回总览等 |
| `board_after` | 动作后应得到的确定状态标识 |
| `object_ids` | 被操作对象的稳定 ID，可被后续事件引用 |
| `viewport` | 黑板局部视口的中心、缩放和范围；不影响笔记与字幕 |
| `presenter_mode` | `full`、`top-right`、`bottom-right`、`middle-left` |
| `presenter_bounds` | 当前矩形窗口与必要裁切参数 |
| `note_action` | 切章节、激活要点、标为已讲、补充条件或保持 |
| `note_text` | 面向观众的简洁中文，不能凭空扩展结论 |
| `production_notes` | 仅制作记录，不渲染；`reason`、`review`、通用 `context` 等也不能自动上屏 |
| `subtitle_id` | 对应中英字幕语义组 |
| `subtitle_emphasis` | 重点词范围、真实原声锚点、放大时长、普通与终态字号、邻字让位方式；完成态保持到本条退出 |
| `motion` | 具体动作、持续时间、缓动与起止值 |
| `priority` | 当前主要注意力位置与其他区域的从属关系 |
| `source` | 事实、引语、数字或原素材时间码的依据 |
| `review` | 需要检验的遮挡、条件、阅读时间或口型问题 |

字段可转成 JSON、CSV 或其他可执行格式；主工程实际采用何种格式应保持一致。不要制作一张无人使用、与最终时间线脱节的文档。

## 指代与证据素材

“这样的二创视频”“我已经发布的两个”“数据还不错”等发言依赖观众看到具体对象。优先使用用户提供或当前项目已确认的真实作品、发布页或数据截图，在实际指代锚点展示；不能用相似示例或抽象板书替代已有证据。全片查找同一对象的多处引用，分别按语境安排，不能插入一次就默认后续观众仍能对应。

- 介绍多个已发布作品时，让所说的作品同时可辨；谈某一个作品的数据时，聚焦对应截图并保留必要上下文。口播若未报数字，可用简短标注帮助观众读图，不给人物合成报数。
- 保留原始截图作为输入。裁切、等比放大、指示线或局部圈画可帮助阅读，但不能改动截图中的作品、数字、指标和状态。记录素材来源及截图时间；“发布一天后的数据”等时间口径仅在用户确认或原始材料支持时标注。播放量、点赞、收藏等指标按实际界面辨认，不能互换；未显示的指标不补造。
- 换用更新的数据截图时，联动检查全片同一素材的引用、主画面数字、右侧笔记和时间标注。原口述中的历史数字保持原意，可在画面区分“录制时”与“更新截图”；不能把新截图沿用为旧的“一天后”等时间口径。
- 区分素材的生产备注与面向观众的内容。“保留录制时的分享，补上更新截图”“后面把这里换成数据图”等编辑安排只进工程记录，不能直接渲染。当前未涉及历史数字比较时，不强塞录制/替换说明；确需区分数字时间点时，用“录制时：…／更新截图：…”等可核实短标注，其他文字围绕当下观点和证据。
- 截图进入以发言指代为锚点，停留到关键内容可读。可暂时替换黑板或录屏区域，保留合适的人物窗口、右侧语境与字幕；退出回到当时的操作状态，不跳过必要动作。截图上的小字不可读时，优先放大目标区域，而非把整张图缩成装饰卡。
- 数据只说明该截图记录的结果。不要从一次表现推出收益、普遍效果、流量保证或留存改善；“数据不错”可保留为说话者对此次结果的评价。

沿用项目现有事件表记录素材 ID/路径、来源与时间口径、真实发言锚点、显示起止、裁切/强调区域和返回状态。复查实际导出中的每次出现，不能仅凭截图已加入素材库就认为引用已经落实。

## 状态模型：保持地图，逐步展开

默认全片维护同一知识画布，黑板分为 `objects`、`connections`、`emphasis`、`viewport` 四类状态。所有对象、连接和短标签具有稳定 ID 与世界坐标，视口只是改变观众看哪里。

- **累计**：建立一个对象后，后续继续连接和补充。适合原因逐渐增加、流程逐步展开。
- **局部**：保留既有地图，把视口移向当前分支；必要时让旧图的一部分留在边缘，提示空间连续。
- **总览**：一个分支讲清后，把视口放回包含主要对象的范围，让观众理解它们如何合在一起。
- **另开地图**：只有原地图已经完成且主题确实变化时使用，记录理由，切换前用一句话或一个视觉关系承接。换章、版面暂满、截图和录屏都不自动触发清空。

连续不代表把全片内容同时缩在一屏。相关章节在同一世界坐标中展开，当前视口只展示可读局部，总览选取需要回顾的范围；通过平移与缩放解决空间问题。章节号属于笔记状态，不能据此重置画布；录屏或证据覆盖退出后回到原地图的当前状态。

上述状态默认必须实际驱动渲染：让观众看到在旧图旁继续写画、拖拽到新局部、再回到同一地图总览。按[完整手绘与连续画布](implementation.md#完整手绘与连续画布)保存稳定对象与真实笔画时间；仅把几个独立图解硬切、复用同名模板或填写相机字段不能代替输出中的空间连续。相机动作由语义决定，不强制每段移动。用户明确选择分页风格或保护既有局部时，按其范围例外。

确定性实现要求：在任意时间点直接跳转，状态应等同于从头播放到该时刻。用绝对时间与固定起止值计算可见性、位置、缩放和描边进度，不能依赖播放历史、实时随机数、只有播放过才触发的累积事件或墙上时钟。视口移动仅作用于黑板容器，右侧笔记、人物和字幕分别控制。

## 根据任务选择人物模式

`full` 指真人录像占满左侧主区域，右侧笔记与底部字幕继续保留，不是人物覆盖整张成片。真人版本开场默认用此模式让观众先看清讲述者；用户明确保护原开头，或钩子必须靠当前图解/实操才可理解时，按其内容与范围安排。纯旁白版本仍沿用无人物模式。

| 语义任务 | 优先模式 | 切换依据 |
|---|---|---|
| 开场给出明确观点、讲个人经验、表达态度 | `full` | 人物表情与语气承担主要信息 |
| 暂无必要图解/操作，或展示已完成、口播继续讲经验与判断 | `full` | 将左侧主区域交回真人交流，避免长期留小窗配无用画面 |
| 建立左侧/下方流程，解释关系 | `top-right` | 为主要图解留连续空间 |
| 展示上方图解或回到整体结构 | `bottom-right` | 不遮住上方关键对象与箭头 |
| 边交流边解释右侧局部 | `middle-left` | 人物仍需存在感，局部图解需要较大空间 |
| 结束一段回顾，进入下一段 | 由下一段任务决定 | 先确认新焦点，再切换，不能为变化而变化 |

同一模式可以保持多句。只因某个句子结束就换角落，并不会增加解释力。切换必须解决至少一件事：交流重点变化、视口变化、空间冲突或段落理解需求。

先完成证据的必要阅读和操作结果展示，再判断是否回到 `full`，不能只因鼠标暂时不动就提前盖住实操。进入新图解或需看操作细节时及时缩回合适小窗；大人像期间旧画布仍保留对象与当前状态，返回时继续同一地图，不清空或另画近似图。切换频率由语义决定，不设每隔几秒、每章几次的配额，也不为增加“刷脸”强行来回跳。

`full` 状态仍需显示必要截图时，可将其放在真人画面中的空白处，不能压住面部、口型和关键手势，且缩到手机大小仍应看清。空白不足时改用证据主画面配真人小窗，不为了同时出现而遮挡任一重点。

先检查目标位置是否遮挡关键图解、笔记、字幕、面部或手势。若发生冲突，重排对象或改变模式；不要临时缩成一个不可读的小人窗。人物移动与黑板聚焦不宜同时跨越大范围，必要时先稳定新焦点，再让人物窗口到位。

## 中文笔记的两层状态

章节与要点分开维护，例如 `chapter = 04` 时，`active_point` 可以依次为隐私、税务、段落小结。章节不变不代表笔记静止。

前置片中高光时，笔记先进入独立的“精彩预告”或“本期高光”状态，不显示 `1/N`。问题钩子阶段只显示该问题和有依据的观看理由，不把后文方法、参数、结论先写出来；进入正文第一章才从 1 开始计数。

正文默认逻辑：

1. 引入一项时，显示短笔记并标为当前；若结论需要后文证明，写成问题或保留条件。
2. 黑板解释过程中，当前笔记保持稳定，避免随每个词反复改字。
3. 进入下一项时，上一项变灰，当前项黑粗并带红点；需要的旧项继续留在纸面。
4. 一组要点完成时，可加入一句有依据的小结，同时黑板回到适当总览。
5. 换章时更新章号与标题，并明确正文为什么进入下一章。

笔记可在论点提出时出现，也可在结论讲清后落下，取决于它是“问题路标”还是“答案摘要”。事件表必须写明这一选择。不要提前显示尚未解释的结论，让观众读完后口播才慢慢追上。

## 动作的先后与时机

以下只是可调起点，必须以真实语音和实际导出为准：

- 熟悉的对象可以在提到其名称前约 0.1–0.3 秒出现，让观众先识别；不能提前揭示悬念答案或让画面脱离语境。
- 因果箭头和结果宜落在解释关系的关键词附近。条件要与结论同屏出现，不能等结论被误读后再补。
- 新对象进入约 0.2–0.6 秒，重点圈线约 0.2–0.5 秒，视口调整约 0.4–0.9 秒。内容复杂、台词紧密时应减少动作而非一律加速。
- 两个高显著度动作可间隔约 0.15–0.4 秒，形成可感知的先后；这不是固定节拍，清楚的语义落点优先。
- 关键图解须完成最后的必要笔画、标签和关系，并停留到观众有时间读懂、对应口播，才可切走或被截图覆盖。用动作完成与阅读结束时间约束覆盖时点；不是仅凭片段长度或“动画做完了”切走。
- 若真实口播过密，先精简图解与笔记；需要改稿/补录时在授权范围内处理，不能用加速动画掩盖理解困难。

描边揭示应服务对象建立过程。默认按[完整手绘与连续画布](implementation.md#完整手绘与连续画布)安排图形、连线和短板书的真实笔画与顺序；长说明移到笔记，不能以整词跳出冒充书写。不能要求观众等待几秒无信息的“画画表演”，首帧钩子可直接显示已完成的手写路径。只有用户明确选择排印风格时才采用对应文字显现方式，并如实记录。

默认声音以清晰真人原声为主。手写音、提示音和转场音是可选设计，不能声称已核验原片使用；若使用应轻量、少量，并在语义重点处实际听检，避免盖住辅音和句末。

## 一组可执行的语义示例

以下是自造主题示例，仅说明编排方法。时间码应在录音完成后填入，不能当成原片复刻时间码；其中论点也必须在具体项目中有证据。

| 口播语义 | 黑板事件 | 人物 | 笔记事件 | 主要焦点 |
|---|---|---|---|---|
| 提出“样机能跑，为什么还交付不了”的问题 | 手机与终点之间画一道门，门上短标“交付条件” | `full`，为问题留少量可见图解 | 激活“从能跑到能用” | 真实钩子与明确障碍 |
| 说明第一个必须满足的条件 | 聚焦门的一侧，增加条件 A 对应物件 | `middle-left` | 当前项“条件 A” | 当前局部关系 |
| 补充第二项与前项不同的条件 | 在同一地图旁增加条件 B，连接共同终点 | `top-right` | A 变灰，B 黑粗红点 | 两项区别 |
| 解释两项怎样共同影响结果 | 回到能看见 A、B、门和终点的总览 | `bottom-right` | 激活有条件的小结 | 整体关系 |
| 给出个人建议或下一步 | 旧图低亮，突出下一步行动 | `full` 或保持合适模式 | 留一个可执行结论 | 人物判断与行动 |

这组的必要结构是“问题 → 局部 A → 局部 B → 整体 → 行动”，而不是这些模式必须按顺序各出现一次。内容只有一项条件时删掉不需要的步骤。

## 前三秒与转入正文

新视频和完整重剪都必须选择材料中最强且真实的结论、问题、感叹、亮点或值得讨论的观点，前 3 秒已经让观众理解其核心。第一帧和前 0–2 秒检查只负责早期可读性与音频入口，不能代替这个钩子。

把钩子写入事件表并记录来源：真实口播时间码、已核实事实或用户确认的内容。可以用人物直接说、一个立即可懂的黑板关系，或两者共同呈现。随后正文要及时建立相关情境、原因、证据或演示，不能只抛一句强话就跳去无关介绍。

### 高光预告与正文分开

从片中提取高光放到开头，是一次预告，不是正文第一章。人物、字幕、黑板与右侧笔记都应表达同一角色：右侧用“精彩预告”或“本期高光”，不显示 `01/12` 这类正文进度。正文开始再从第 1 章编号，后续总章数只计算正文。

选定问题式高光时，剪到问题完整成立即可。后面的回答留在正文对应经验或实操段，不把回答紧接到预告里，也不通过笔记、板书、流程图或新写的引导句提前揭底。比如用“同样好的视频，怎样少花积分？”引起好奇时，开头不同时显示具体分辨率和处理步骤；方法在正文讲到它时才出现。这是编排示例，实际发言、方法与条件仍以本期素材为准。

可以用真实的案例范围或待解决的问题说明观看理由，但不能凭空写“后面更炸”“保证省一半”等承诺，也不把“提高数据”写成已验证结果。制作记录注明预告源时间码、正文落点和回答位置，复查观众能否找到预告所承诺的内容。问题式预告可以把完整答案保留到相应正文，仍需用自然衔接让观众知道正在看怎样的实践。

用户明确要求保留原开头或仅修改别处时遵从范围，并记录该限制。不要为遵循风格而擅改被要求保留的部分。

## 验收顺序与记录

先审开场、最复杂图解和跨章交接，再审完整导出。修改了节奏、音轨、字幕或窗口后，复查受影响片段及相邻衔接；不要只看编辑预览。

必检：

- 实际导出 0–3 秒到首个完整观点：以正常速度看并听，记录核心钩子何时可理解、如何连正文、音频是否干净进入。高光预告标识与正文章号明确区分；问题预告没有提前显示答案，正文确实兑现其问题与观看理由。
- 语义落点：对象、箭头、人物位置和当前笔记是否在观众需要时出现；是否有未解释即消失的信息。
- 阅读顺序：同一时刻主要焦点是否明确，是否让观众同时读新字幕、新笔记和复杂新图。
- 连续性：局部如何回到整体；旧项变灰是否合理；切换人物位置是否遮住关系。
- 字幕与声音：中英忠实、语义完整、不挡嘴或图；原声中的录制失误已实际剪除，不能靠精简字幕掩盖重复发言。检查接缝前后语义和气口，保留有目的强调及必要操作说明，原声清楚、可选音效不干扰。
- 实现稳定性：关键时间点直接跳转与顺播状态一致；导出尺寸、时长、音画同步与资源引用正确。

生产记录只写实际做过的检查，例如“已正常速度观看导出 00:00–00:16 并听检，02.4 秒前问题核心可理解；16 秒内接入第一项原因”。若只能做静帧或文件检查，应明确其边界，不能写成已完成观看、听检或观众留存验证。
