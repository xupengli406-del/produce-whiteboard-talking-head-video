# 从用户视频到可验收成片

## 直接接片的默认处理

输入是视频时，先看实际素材和现有工程。保留原件；默认沿用原画幅、语言和原声，以当前参考选择表达强度。原片中说了什么、重音在哪里，依据实际声音和字幕对齐确定；自动转写只作为初稿，重点词需核对。

本次授权是网感处理时，完成原声剪辑、字幕、相应画面变化和声音配合即可；不附带重写稿、换脸、合成发言、制作封面或发布。若用户同时要求这些内容，再进入相应流程。

已有源素材时不反复索要“平台、受众、风格、密度”问卷。可从画幅、片段内容、用户已有偏好和参考判断；只在会实质改变输出且无法推断时问缺失信息。

## 先确定能力和资产

| 本次需要 | 应确认的实际能力 | 缺失时的推进方式 |
|---|---|---|
| 查看/导出视频 | 实际可用的编辑器或渲染引擎与导出路径 | 用已选工程的能力；新工程读取当前视频生产入口 |
| 对齐字幕和重音 | 实际音轨、字幕或可用转写与校对路径 | 优先已有字幕/本地路径，不用猜测语句代替听取 |
| 人物遮挡文字 | 视频分割/抠像与动态 alpha 输出 | 先落实抠像能力，普通裁切不算人物抠像 |
| 指定动画预设 | 同名预设的实际预览 | 已核对的通用等效可用，但记录实现方式 |
| 字体、图标、烟花、声音 | 本地文件、已安装字体或可用素材解析 | 按本次语义取得素材并预览/试听，记录实际依赖 |
| 定格与调色 | 任意源时刻取帧、静帧保持及本引擎颜色处理 | 先取真实帧，再在工程中设置停留与处理 |

这里是本次选择方法后的能力检查，不是要求装齐所有工具。未经核对的预设、找不到的声音或未取得的 alpha 不能记成已实现。

## 将表达转换成工程动作

先确定真实锚点与完成态，再选择适配的技法/配方。可以使用完整联动增强同一语义，也可以根据用户素材选其中的适配组合。库里全部保留，不意味着每条视频强行使用所有方法；首批 37 项不因新增授权方法而改号。

声明用了一个完整配方时，应实现其全部成员；只使用部分成员就明确写成“适配组合”，列出实际使用项与因素材变化而替换的项目。基底字型、描边等静态处理也是组合的一部分。

每个动作明确：作用对象、起止时间、原声/动作锚点、实际参数、依赖文件、实现方式。多种方法可以指向同一表达重点；方法作用于不同对象时不要合并成一个含糊的“放大效果”。

真人项目另按[主画面趣味与焦点规范](../visual-rhythm.md)在同一记录写清动作峰值、完成态、颜色角色、旧注释退出／降级点与联动对象。趣味并不等于增加另一组文字或全用金框；同色、多框和多效果按是否指向同一阅读任务判断。查看真正输出的进入、峰值、停稳阅读、退场及后续普通画面，不能用代码存在或技法名字代替可见效果；V24强调依原规则保持至句末。

## 可检查的剪辑计划

完整新剪辑、多层联动或重排/变速使用 edit-plan.json；简单局部修正可更新现有工程记录。可复制[字段示例](edit-plan.example.json)，替换为用户素材与本次实测信息。该文件是结构示例，不能直接当作用户的剪辑计划或转写。

必要组成：

- `output`：画幅、帧率、成片时长与当前导出路径。
- `sources`：真实输入路径、实测时长与是否包含声音；路径相对计划文件所在目录。
- `clips`：源区间到成片区间的映射；恒速为 `play`，定格为 `freeze` 并给出 `source_time`；主画面 `primary: true`。
- `assets`：实际素材路径和类型；尚未取得时可以 pending，但不能通过实现/交付检查。
- `objects`：文字、画面、素材、前景、画面组或声音；绑定片段及依赖。
- `effects`：稳定方法 ID、作用对象、时间窗、锚点、参数和计划/实现状态；参数值为本次决定。
- `requested_methods` / `requested_recipes`：本次承诺使用的方法与完整配方。实际变更同步更新，不用空声明掩盖遗漏。
- `review`：真实观看、试听的状态及证据或具体限制；用户选定另外记录，不能自动推定接受。

导出后用实际媒体探测结果填写 `output.inspection`：`duration`、`width`、`height`、`has_audio` 和当前文件 `sha256`。这组数值来自真实输出，不从计划照抄；文件哈希将探测记录绑定到当前导出，避免旧导出检查结果被误用。正常声音默认保留；明确要静音时在 output.has_audio 记录本次决定。

[方法执行约束](method-contracts.json)保存作用对象、冻结／alpha 等前提及显式语义参数的合法值，不重复详细技巧内容。V24 新记录可设 `params.inline_caption: true` 并给出 `caption_start`、`caption_end`、`emphasis_duration`、`end_behavior: "hold-until-caption-exit"`。旧计划未写新字段仍可读取；显式要求回缩则检查失败。新增方法时同步维护此文件。

检查命令（路径按当前 Skill 位置使用）：

```text
python3 scripts/validate_edit_plan.py /实际项目/edit-plan.json --stage plan
python3 scripts/validate_edit_plan.py /实际项目/edit-plan.json --stage implemented
python3 scripts/validate_edit_plan.py /实际项目/edit-plan.json --stage delivery
```

该工具检查时间、对象、配方成员、层级/同步声明、文件与状态；不渲染视频，也不能证明 alpha 边缘、画面效果或听感良好。通过记录校验后仍按下面流程查看实际输出。

## 实现、导出和检查的状态

1. **计划：**真实源时间和目标对象成立；可有明确登记的待取素材。
2. **已实现：**选择的效果存在于实际工程；素材已就位；动态前景与底片同步；原版预设经过本次预览，通用近似如实记录。
3. **已导出：**当前输出文件存在，实际时长、画幅与声音经过探测；检查的是此文件，不是旧导出或仅预览页面。
4. **实际观看/试听：**正常速度查看连续动作、转场和结尾，听原声与效果配合。记录所看的文件和有问题的时间点；无法完成的项目写明具体限制。
5. **完成：**修复实际发现的问题并更新同一当前导出，保留可复现工程与依赖。没有用户选定证据时不称“用户已接受”。

检查重点依所用技法选择：遮挡看手指/头发/层级，镜头看裁切与同步，蒙版看指向与边缘，字幕看锚点和完成态，音效听落点/对白/尾音，定格看源帧和恢复边界。不要给无关方法做全套重复检查。

使用 [V24 行内字幕强调](text.md#V24)时，检查自然初始态、真实发声锚点前、动画中、完成态、句末保持、退出与下一条初始态，顺序播放和随机 seek 都一致。检查当前导出中的空槽、邻字跳位、重叠、裁切或异常换行，并正常速度查看词语衔接；仅完成态好看或计划记录通过，不能代替这些检查。[可复用组件与浏览器回归](inline-emphasis.md)用于验证组件行为，不证明用户成片已经审过。

## 有依据的自迭代

实际使用发现“对象混淆、时间映射错误、缺资产、配方半实现、预览与输出不一致”时，记录触发条件与真实证据，在对应条目或执行规则中修正，再用同类案例验证。新的独立做法继续按收录模式入库。修正一个问题不等于要降低所有视频的效果密度，也不代表用户拒绝现有交付。
