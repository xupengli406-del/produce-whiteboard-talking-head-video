# 获取公开参考视频与建立时间线

## 按本次可用条件取得内容

优先使用用户已经给出的本地文件或可访问页面。链接打不开、正文解析不返回视频时，继续检查可用播放页、公开解析能力和本地读取工具。取得真实视频之后建立时间线与取帧；没有取得视频但页面能播放时，可通过页面进度和截图核对，保留能确认的内容与具体缺口。

公开参考链接与用户私人待剪素材是不同输入。公开解析服务只接收本次提供的公开链接，不因此上传用户私人视频、原声或浏览器登录信息。临时播放地址可能到期，应保留实际本地输入与稳定原页面地址。

## 首批抖音参考的实际成功路径

以下是 **2026-10-08 已成功执行的历史记录**，接口和服务状态在下次使用时需要重新核对，不能假定长期有效。

1. **确认同一内容。**短链 `https://v.douyin.com/RDvreAj35Fk/` 对应页面 `https://www.douyin.com/video/7693904484166094089`。标题、作者和视频 ID 用于检查下载的是同一条内容。
2. **尝试页面读取。**打开过浏览器开发者工具，尝试检查页面；这不是进入作者创作后台。浏览器路径没有成为最终下载来源。
3. **取得公开解析结果。**使用 `https://demo.douyin.wtf` 的公开演示 API。GET `/api/v1/auth/demo` 取得该服务公开提供的演示登录信息，POST `/api/v1/auth/login` 建立演示会话，再 POST `/api/v1/parse?wait=25`，正文为本条公开视频 URL。演示凭据与会话只在操作内存中使用，没有提取、发送或保存用户浏览器 Cookie。
4. **保存真实视频。**解析结果返回同一条视频的公开播放流，按清晰度选择 1440 × 2560 的地址并下载到本地。元数据时长为 21134 ms；标题、作者、ID 与给定页面吻合。本例下载客户端使用 curl 成功，另一路请求客户端发生过 TLS 失败，因此换用了可工作的读取路径。
5. **建立证据。**读取本地媒体时长，在标注时间取帧，核对左侧原片、右侧作者标注和声音素材卡片，保留来源页面、时间和文件 SHA-256。剪辑库因此有可核对时间线，不只依据页面标题总结。

本案例的覆盖清单随方法模块保留；原视频与13张截图是本地证据输入，不随公共Skill分发。迁移维护时已经逐SHA保全14个原文件；复核时使用自己保留的证据目录，不因公共包有清单就宣称媒体已在包内。查询具体媒体证据时读 [case.md](cases/lc-vol12/case.md) 与 [coverage.json](cases/lc-vol12/coverage.json)。

## 可复用的核对标准

- 解析、播放或下载成功之后，核对作品 ID、作者、标题与时长；不要把推荐视频或其他同名作品当成用户指定内容。
- 原页面地址与媒体文件的哈希用于追溯，临时 CDN URL 用于本次下载；不将它当永久引用。
- 记录取得路径与失败点，避免反复使用已失败的同一种路径；也不把某次客户端失败写成该平台永久无法访问。
- 比较快的文字动画、遮挡和转场需要查看前后帧或实际播放；只看一张预设缩略图不能确认其完整动作。
- 音效名称从卡片读取，实际使用长度和听感仍要听音轨；缺少听取时注明已确认的是卡片信息。
