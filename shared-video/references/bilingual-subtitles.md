# 默认中英双语字幕

用户于2026-10-15明确要求增加双语字幕。后续完整真人视频默认在成片内显示中文主字幕与英文辅助字幕，并交付 `字幕_中文.srt`、`字幕_英文.srt`、`字幕_中英双语.srt`；本次明确单语、已有选定版本的局部返修或不含字幕的任务按其范围执行，不重做历史视频。

## 一条真实原声、同一母时间线

1. 先完成原声精剪，再以实际发言校对中文字幕。产品经理、事实性文档、产品名、缩写、人名、数字、否定和限定需核对，不能按初稿反推未说过的词。
2. 按完整词语、句意、语气和真实字宽分组。中文不是逐字蹦跳；英文按对应意思翻译，不能逐词硬对齐或增减观点。保留自嘲、疑问、条件和语气强度，不强化结论。
3. 英文与中文共享每条字幕的起止时间。若英文太长，先用忠实且自然的短表达和合理换行；必要时把中英文一起重分组并重新对齐音频，不能独自拖长英文到下一句，也不能一路缩字号。
4. 翻译只能使用已核对的最终原声／中文字幕；姓名、品牌和技术词统一片内写法。有歧义的词回查素材，不能靠英文把错词掩盖掉。

## 画面层级

中文为主阅读层，英文为次阅读层。普通短句可中文一行、英文一行；长句按真实字宽排布，必要时调整容器或共同分组，不能用固定字数硬截。检查最长英文、混排数字、两行中文和重点词放大后的整体高度，避开人脸、资料、小窗和平台安全区。

双语共享语义但不同时争抢注意力：默认中文承担主要强调，英文保持清楚稳定；英文本身是讲解对象时再针对它突出。行内强调只采用[网感V24](editing-methods/text.md#V24)的最新规则，不能由英文行的布局或下一次初始化把中文强调态重置。

引用原片已有烧录字幕时保留真实原片，不再叠一套相同译文。本人评论用独立双语字幕带；额外科普和引用来源使用不同信息层级。字幕忠于声音，不能把侧栏概括或作者观点伪装成原片发言。

## 可复用的对齐与导出

使用 `scripts/prepare_bilingual_subtitles.py`，以校对后的中文SRT和逐条翻译JSON生成三份字幕。JSON每项为 `{"index": 1, "text": "English translation"}`，index对应原中文cue编号；英文允许有意换行。脚本不做翻译、不判断语义和屏幕可读性；缺译、重号、额外条目、空译文、无效或重叠时间会报错，避免静默错配。

```text
python3 scripts/prepare_bilingual_subtitles.py --zh /实际项目/校对中文.srt --translations /实际项目/英文逐条翻译.json --output-dir /实际项目/交付 --duration 实际成片秒数 --recovery-dir /实际系统废纸篓/本次任务
```

脚本相对本Skill目录，调用时使用实际安装位置。`--recovery-dir` 指向本次已确定的系统废纸篓恢复目录；macOS省略时可发现已有用户废纸篓并建立唯一任务目录，找不到可靠位置就拒绝覆盖既有输出。相同内容重跑跳过；替换前把旧文件可恢复地移入该目录并追加 `恢复映射.json`。中文输入与中文输出解析到同一文件时保持输入字节和符号链接，避免把用户原字幕当生成物改写。已保留的可用双语流程可以继续使用，但必须满足同一时轴与检查要求；不为采用工具强迫改写已确认字幕。

## 导出检查

三份SRT覆盖同一最终发言，编号、起止、顺序对应；中英双语文件逐条中文在前、英文在后。查看实际编码视频的开头、中段、后段、最长句、重点词发声前后与接缝，确认翻译与当前发言匹配、阅读时间足够、无漂移、无重复叠加和截字。翻译检查与排版检查分开；时间戳相同不代表翻译正确或一定读得完。交付说明写明视频已内嵌双语及三份SRT的用途，避免平台再叠字幕。
